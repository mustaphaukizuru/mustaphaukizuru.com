Three tiers, one platform

How the eleven roles from the expert audit map onto mustaphaukizuru.com — organized by how tightly each one is engaged, not by seniority. Engagement depth drops from Tier 1 to Tier 3; independence from the platform rises the same direction, which is deliberate for the two roles that have to be able to fail the platform's own audit.

TIER 1
Core Build Team
Embedded. Continuous. Owns the critical path.
TIER 2
Specialist Contractors
Engaged per phase. Part-time, scoped deliverables.
TIER 3
Independent Advisory
External. Periodic audit only — never embedded.

Where you sit today

Right now you are Tier 1 — Product Manager, Backend, Frontend and Designer in one person, which is exactly the single-maintainer risk your own Description doc names as R3. That's a reasonable place to start; it stops being reasonable the moment Commerce or Compliance ships without a Tier 3 sign-off.

Sequencing: contract Tier 2 roles per phase as the roadmap reaches them — QA before Phase C (commerce hardening), SEO Strategist before Phase E (growth). Retain Tier 3 as periodic engagements only, never headcount: a Security Engineer and Legal Advisor embedded in the team lose the independence that makes their sign-off worth anything, which is the entire reason R7 in your risk register exists.
