## PART I — GOVERNANCE

### 1. Catalog Scope and Purpose

This catalog defines the complete set of professional services offered under the Mustapha Ukizuru brand. It is the single source of truth for what is sold, how it is sold, who it is sold to, and how it is delivered. The catalog supports four operational uses: customer-facing marketing on mustaphaukizuru.com, sales conversations and proposals, internal delivery planning and pricing, and quarterly portfolio governance.

### 2. Catalog Architecture

The catalog is organized in four layers, top-down:

- **Source** — the brand and capability stack: Mustapha Ukizuru.
- **Categories** — six top-level service families.
- **Services** — atomic SKUs within each category, each independently sellable.
- **Deliverables** — the specific outputs produced within each service.

Solutions (multi-service bundled engagements with a single all-in price) are composed from atomic services and documented separately in Part IV.

### 3. Naming Conventions

**Service identifier schema:** `UKZ-{CC}-{NNN}`

- `UKZ` — brand prefix (Mustapha Ukizuru)
- `CC` — two-letter category code
- `NNN` — three-digit sequential service number within category

**Category codes:**

| Code | Category |
|------|----------|
| CS | IT Consulting and Strategy |
| BD | Brand and Digital Presence |
| IC | IT Infrastructure and Cloud |
| WD | Web, Application and AI Development |
| ET | EdTech Implementation and Training |
| MS | Managed Services and Support |

**Service name pattern:** `{Noun phrase} + {format suffix}` (for example, *Technology Assessment and Audit*, *Custom Web Application Build*, *Fractional CTO Retainer*). Format suffixes telegraph the consumption mode in two seconds.

**Approved format suffixes:** Audit, Assessment, Sprint, Build, Workshop, Cohort, Program, Retainer, Service, Implementation, Setup, Rollout, Migration, Engagement, Pack, Toolkit.

### 4. Metadata Schema

Every service record contains the following fields:

| Field | Description |
|-------|-------------|
| ID | UKZ-{CC}-{NNN} unique identifier |
| Name | Service name following naming convention |
| Outcome | One-sentence value statement |
| Audience | Target segment(s): EDU, SMB, IND, or combinations |
| Format | Service, Product, or Hybrid |
| Engagement | Audit, Sprint, Build, Workshop, Cohort, Retainer, etc. |
| Duration | Typical delivery timeframe |
| Pricing model | Fixed scope, T&M, monthly retainer, per-seat, per-unit |
| Tier | 1 (Flagship), 2 (Standard), or 3 (Specialized) |
| Status | Active, Beta, Roadmap, Retired |
| Deliverables | Specific outputs produced |
| Related | Cross-references to other services |

### Appendix A — Glossary

**Catalog Item.** An atomic service SKU as defined in this catalog.
**Solution.** A composite offering composed of multiple Catalog Items, sold as one transaction.
**Engagement.** Any sold transaction, atomic or bundled.
**Tier.** Service prominence level (1 Flagship, 2 Standard, 3 Specialized).
**Retainer.** Recurring monthly engagement with defined scope and SLAs.
**Sprint.** Time-boxed delivery with fixed scope, typically 1–8 weeks.
**SLA.** Service-Level Agreement defining response times and availability.
**LFPDPPP.** Mexican federal law on data protection (Ley Federal de Protección de Datos Personales en Posesión de los Particulares).
